# Adding a dataset

A new dataset is useful only if a reader can tell what its label means and how the label was
made. A pull request that adds a dataset must do all of the following.

1. **Write a loader in `src/data/`.** The docstring states the label rule in one sentence and
   cites the file and field the label comes from. Record the pinned version (commit or Hugging Face
   revision), and pass files in a fixed order. Iterating over a `set` of strings depends on
   Python's hash seed, so sort every set before you draw from it.
2. **Classify the provenance** into one of three kinds:
   - executed runs with a label the dataset defines
   - clean traces edited by code to plant an anomaly
   - trajectories that were never executed or were generated by a model
3. **Name every feature the label ties by construction.** Use the three rules in
   `docs/prereg-v50.md`: the label is computed from the feature's actions; an injector shifts the
   feature by ≥0.2 pooled SD on clean traces; or the label concept adds or removes actions. Add a
   row to `docs/label-mechanism-audit.md`.
4. **Add a test in `tests/`** that loads a small synthetic fixture and checks the label rule. The
   test must fail if the label is inverted.
5. **Add the dataset's license to `DATA_LICENSES.md`,** quoting any restriction. Do not commit
   the data.
6. **Report the new dataset's results with and without its construction-tied cells.**
